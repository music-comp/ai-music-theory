# Quick Definition
The rejected view that the coda functions as a "terminal" development section -- a view now largely in disrepute because it fails to differentiate the fundamentally different tonal and formal organizations of the development and coda.

# Core Definition
The analogous formal positions of development and coda -- both following similar sections (exposition and recapitulation) -- have led some earlier theorists to view the coda as a "terminal" development, particularly in the hands of Beethoven. But this view, now largely fallen into disrepute, fails to differentiate the fundamentally different tonal and formal organizations of the two sections. The development generates maximum tonal instability and explores remote keys; the coda remains primarily in the home key. To say that the coda "refers" to material from the development is not to claim that the coda functions or structures itself like the development.

# Prerequisites
- **Coda**: The section mislabeled as a "terminal development"
- **Development section**: The section to which the coda is erroneously compared
- **Development reference in coda**: The legitimate compensatory function

# Key Properties
1. The term "terminal development" is now largely rejected
2. Development and coda have fundamentally different tonal organizations
3. Development: maximum tonal instability, exploration of remote keys
4. Coda: remains primarily in the home key, after-the-end function
5. Reference to development material is a legitimate compensatory function of the coda
6. Reference does not imply functional equivalence
7. The coda may use development-like techniques (sequences, model-sequence) but in a tonally stable context

# Construction / Recognition
- If a passage follows the recapitulation and uses sequential technique, check the tonal context
- If the harmonies remain closely bound to the home key: it is a coda, not a development
- If genuine tonal instability and remote-key exploration occur: reconsider the formal boundary

# Context & Application
This terminological clarification matters because calling the coda a "terminal development" misrepresents its formal function. The coda expresses an after-the-end temporal quality; the development generates instability. Even Beethoven's most development-like codas (Third Symphony, Seventh Symphony) maintain home-key centrality.

# Examples
- Mozart, Symphony No. 36 ("Linz"), K. 425, i, m. 269ff (ex. 15.4): coda derives material from the development's core but treats it in the stable context of the home key

# Common Errors
- Calling the coda a "terminal development" (fails to recognize different tonal organizations)
- Confusing reference to development material with development function
- Assuming development-like techniques (sequences) automatically create development function

# Common Confusions
- **Reference vs. function**: Referencing development material is not the same as functioning as a development
- **Technique vs. context**: Model-sequence technique in a tonally stable context is fundamentally different from model-sequence technique that explores remote keys
